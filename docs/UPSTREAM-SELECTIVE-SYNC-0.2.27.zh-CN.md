# 0.2.27 上游修复的选择性同步

个人分支基线：`52e2ae4ff1279a6851fc80a941eb5d89b0b9a9d8`（`0.2.26-precision.4`）。
上游来源：`kriskwok/DiPlay` 标签 `v0.2.27`，提交 `b8e0dda0897a07ab1680629839da017f73932937`。
本次按功能适配四项修复，不将整个上游提交标记为已合并。

## 合入内容

1. 更新网络：网络选择排除 VPN；前台最新版查询、历史列表、APK 和校验文件下载均使用选定网络的连接工厂。后台检查沿用同一网络选择器。只绑定更新请求，不改变 CarPlay 的进程网络。没有合适网络时，前台保留普通连接的回退路径。
2. 有线启动超时：首次发送 `carplay-start-session` 后等待 30 秒；仍未建立 AirPlay 会话则报告失败，交由既有重试机制恢复。重复发送不延长时限；会话建立、控制循环退出或控制器关闭时取消定时任务。
3. 重试竞态：已排队的重连任务发现同一代控制器恢复运行、且没有再次丢失连接时，不再拆掉该连接。恢复后再次失败、控制通道结束或传输丢失仍允许重试。
4. 软件 Opus 容错：捕获 Concentus 编码时的 `AssertionError`，丢弃该帧并尝试重置编码器；后续帧继续编码，错误报告保留既有次数上限。

## 后续适配：启动时已插线的 iPhone 与临时采集清理

在 `precision.6`（`91c9b59c`）基础上继续选择性吸收上游 `b8e0dda0` 的两项改动：

1. 移除有线连接中临时启动的 `com.apple.syslog_relay` 手机日志服务和最多两分钟的后台读取线程。保留普通状态／错误、连接 I/O 诊断、256 字节分块发送、认证、配对恢复和启动看门狗。
2. 保持原有开机启动入口和开关判断；仅在“打开应用后自动连接”开启、首页启动、认证配置可用且没有既有会话时，读取当前 USB 列表。发现 Apple USB 设备则优先使用有线连接，否则沿用保存的默认连接方式。该匹配规则与现有 USB 插入入口一致，不另行识别产品型号。

不复制上游绕过开机启动开关或每次 USB 插入就重启控制器的行为。检测不需要预先取得 USB 权限，后续授权和连接继续交给现有 Host 与 USB 重枚举状态机。USB 服务缺失或扫描失败时回退到保存的默认连接方式。

自动连接排队执行前会再次确认开关、首页、配置和会话状态；重复排队只保留一次。期间已有连接开始、用户关闭自动连接、转入设置或 Activity 退出时，不停止现有会话，也不强制打开投屏。

本次不更改启动设置的默认值、版本号、更新源或已发布 APK，也不包含光感兜底、音乐积压丢包和高德后台清理。

## 默认启动设置的后续提交

上述启动适配完成后，另行纳入此前保留在工作区的默认值修改：未保存“开机启动”时默认开启，未保存“打开应用后自动连接”时默认开启，未保存默认连接方式时选择 USB。

已有的开关值和默认连接方式保持优先：保存过的关闭状态不会被开启，保存过的无线或“上次使用”方式不会被覆盖。未知连接方式仍按原有兼容规则回退到“上次使用”。本次只改变读取未设置项时的默认值，不执行设置迁移或强制写入。

这组默认值与 `f44ddca4` 的启动适配一起提交到个人 GitHub 分支；版本号和 Release APK 保持不变。
