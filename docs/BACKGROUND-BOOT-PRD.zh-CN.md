# 车机后台启动：需求与技术方案

状态：已实现本地测试功能，实车验收未完成。本文以 CarPlay 1.2.0、`lincoln-0.2.20` 现有启动和连接行为为基线；自动化测试与模拟器结果不等同于实车验收。

2026-10-27 开发进度：新增默认关闭的设置和开机分流；无线后台服务会主动尝试选定 iPhone 的 RFCOMM，并将成功的连接一次性移交现有控制器。预连接在发送 StartSession 前失败时，尝试一次原有无线启动流程。1920×1080 Android 11 模拟器已验证开关位置、无手机开机停留桌面、无线后台服务运行和手动打开后取消等待；假蓝牙连接的单元测试验证了套接字所有权转移。默认模式在模拟器仅记录了启动请求，系统桌面仍可能限制页面拉起。真实 USB 插入、真实 iPhone 无线握手、三种 Wi-Fi 模式及车机固件尚未验证，不得据此声称实车连接已经验收。

无线实现的现状：已同时接入系统 ACL 事件和后台主动 RFCOMM 连接，主动连接成功后向原有控制器移交同一套接字。每轮等待具有唯一标识，通知、线程、延迟任务和未领取的套接字按该标识隔离。旧事件不能消费或清理新一轮等待；手动打开、更换手机或关闭相关设置会取消旧等待。

本轮对抗性审查修正：

| 问题 | 修正与回归 |
| --- | --- |
| 同次开机取消再等待，旧通知／旧事件可能被当成新请求 | 等待标识与 PendingIntent 身份绑定；取消时使对应通知动作失效；覆盖旧请求不能消费或取消新等待。 |
| 服务快速停止再启动，旧 worker 仍被复用或迟到清理影响新 worker | 新一轮替换 worker，所有检查携带等待标识；停止使用对应 startId；覆盖旧停止请求不影响新一轮。 |
| 连接页面打开后，排队连接可能忽略用户刚修改的设置 | 执行前复查页面代次、当前会话、开关和选定手机；覆盖后台请求失效与旧蓝牙唤醒入口仍可用。 |
| 已有会话时重复开机事件可能再次启动蓝牙探测 | 后台开机入口和探测服务都检查已有／正在停止的会话；不停止现有会话，不保留断开后可复活的旧等待。 |
| 主自启动关闭时，后台开关未灰显 | 复用现有开关行显示依赖，保持已保存选择；父开关切换后立即刷新。 |

发布前仍须用真实 iPhone 验证 Wi-Fi Direct、车载热点、已有 Wi-Fi 的握手和断开重连，以及车机冷启动、USB 插入和休眠唤醒。预连接改变了蓝牙连接与网络准备的先后时机；单元测试只能验证资源交接和失败路径，不能证明手机端时序兼容。Android 后台页面及通知限制也需要在目标车机确认。

审查后复核：后台启动路由、服务、通知失效、资源归属、开关依赖、设置备份、语言及布局定向测试均通过；最后一次单独补跑的蓝牙唤醒测试为 40 项。主应用 `assembleDebug`、`lintDebug` 通过，没有执行全仓测试。修正后的构建在 1920×1080 Android 11 模拟器实际重启后，系统桌面保持前台、后台探测服务运行且生成等待标识；手动打开应用后标识移除、探测服务停止。模拟器采用只读临时启动，验证结束后已关闭。

## 目标与发布底线

用户可选择车机启动时不因开机本身展示 DiPlay 首页；尚无有效手机连接触发、用户也未主动发起连接时，保留原车桌面。用户插入 iPhone、检测到有效的无线手机连接触发，或手动发起连接时，可以立即打开 DiPlay 连接首页，按既有流程建立 CarPlay。用户也可以随时手动打开 DiPlay 首页。这里的后台目标是“等待阶段不打扰”，不是要求整个 CarPlay 会话在后台建立。

**硬性底线：新增开关默认关闭。开关关闭或老版本升级后未设置该选项时，开机自启动、USB／无线自动连接、权限、显示、返回、断开重连及用户手动打开均应与 1.2.0 保持一致。**不为了后台模式改变原有开关的默认值、保存值或功能。无法验证该基线时不得将功能作为完成发布。

## 现有链路与约束

- `BootReceiver` 在收到 `BOOT_COMPLETED` 且“车机启动后打开”已开启时直接启动 `DiPlayActivity`。
- `DiPlayActivity` 在首页恢复时根据“打开 CarPlay 时连接”、已插入的 iPhone 以及默认连接方式启动连接。开机前已插线的手机通过 `PreattachedIphone` 扫描，不能依赖 USB 插入事件重放。
- Android USB 设备匹配目前直接指向 `DiPlayActivity`；已运行的连接控制器也会监听 USB 插拔。指定手机的蓝牙连接广播同样可以启动页面。
- 当前开机扫描只检查 Apple 厂商 ID；系统 USB 过滤器也包含 CH341 认证设备。Apple 厂商 ID 不足以证明设备就是 iPhone，USB 重新枚举还可能改变设备实例。后台路径必须沿用经过验证的设备发现和认证流程，不能只凭一个广播就认定 iPhone 已连接。
- `DiPlaySessionService` 用于保持已建立或正在建立的连接；控制器、权限流程、画面尺寸和 Surface 的创建目前与 `CarPlayHostActivity` 生命周期耦合。单纯在开机时启动现有 Service，不能保证等待和连接都会工作。
- 系统和车机厂商可以限制开机广播、后台服务、页面拉起、USB 默认处理及运行时权限。Android 新版本对后台启动页面，以及从后台使用麦克风、定位前台服务有额外限制；需要按设备验证，不承诺绕过系统安全限制。

## 产品需求

### 设置与外观

- 入口：**设置 → 连接 → 自动连接**，紧邻现有“车机启动后打开”。
- 名称：**后台启动**；英文：**Start in background**。说明建议为“车机启动后不自动打开首页，开始连接时再显示。”英文为 “Keep the home screen hidden at startup until a connection starts.” 具体文案须与实现后的行为一致。
- 复用现有设置行、开关、颜色、图标体系、间距、尺寸和文字层级，不增加醒目新卡片或改变其他设置布局。开关文字保持清晰，优先单行；窄屏和大字体允许说明正常换行。
- 仅支持现有简体中文与英文，默认关闭。车机自启动关闭时该项灰显或不可操作，同时保留用户此前选择；重新开启车机自启动后恢复该选择。灰显状态应明确其依赖，不误导用户以为数据被清除。
- 将新配置纳入现有设置备份／恢复及诊断；升级旧配置时按关闭处理。

### 行为

| 车机自启动 | 后台启动 | 预期 |
| --- | --- | --- |
| 关闭 | 任意保存值 | 开机自启动入口不主动启动页面或等待服务；手动打开、系统 USB、蓝牙唤醒及电话监听保持现有行为。 |
| 开启 | 关闭／未设置 | 原有开机流程不变。 |
| 开启 | 开启 | 开机本身不展示首页；尚无有效手机连接触发、用户也未主动连接时停留在原车桌面，实际触发连接后可以展示连接首页。 |

“车机自启动关闭”只禁止该开关触发的开机启动，不取消系统 USB 附着入口、独立开启的蓝牙唤醒或原有电话监听等行为。后台启动开关只改变开机入口的策略，不替其他独立入口静默改设定。

### 自动连接与事件入口

以下约定仅适用于“车机自启动”和“后台启动”均开启时；后台启动关闭时严格沿用 1.2.0。

| 事件或状态 | 对应设置 | 预期 |
| --- | --- | --- |
| 开机时 iPhone 已插入 | “打开 CarPlay 时连接”开启 | 扫描设备，按现有 USB 优先策略进入连接；不得等待系统重放插入事件。 |
| 开机时 iPhone 已插入 | “打开 CarPlay 时连接”关闭 | 不因开机扫描主动发起连接；用户手动打开时继续沿用现有设置。 |
| 开机后 iPhone 插入 | 不等同于“打开 CarPlay 时连接” | 保留现有系统 USB 附着入口及授权处理，不因另一个自动连接开关被关闭而擅自屏蔽；系统可能显示选择器。 |
| 无已插 USB，默认无线，且“打开 CarPlay 时连接”开启 | 默认连接方式为无线或解析后为无线 | 无手机时开机不因无线等待而打开首页；检测到可靠的手机连接触发后，允许打开连接首页并沿用现有连接流程。触发方式须实证，不能擅自要求用户额外开启蓝牙唤醒或把无线自动连接改成手动连接。 |
| 选定 iPhone 蓝牙连接 | “iPhone 蓝牙连接时连接”开启 | 保留独立蓝牙唤醒语义，并与开机、USB、手动连接去重；关闭时不额外启用该入口。 |
| 用户手动打开 DiPlay | 按现有“打开 CarPlay 时连接”处理 | 有会话时复用现有会话；无会话时正常进入首页，不因后台模式阻止用户操作。 |

开机时系统可能随后另行投递 USB 附着事件；是否由系统交给 DiPlay、选择器或其他应用决定，不属于应用可无条件控制的部分。它与开机扫描必须分别诊断和去重，不能把“开机扫描未主动连接”误认为一定不会收到独立的系统 USB 事件。

- **开机前已插 iPhone**：开机后检查设备，按上表的 USB 优先与自动连接策略处理，不重复启动连接；连接需要用户授权时走可见授权流程。
- **开机后插 iPhone**：通过系统 USB 入口或经验证的设备事件识别候选设备，复用既有连接与授权流程。按现有策略完成设备认证前，不把 Apple 厂商 ID 或 CH341 附着单独当作 iPhone 连接成功；避免无关配件被误当作已连接手机。保留 USB 重枚举、认证器使用及授权流程，不能通过缩小匹配范围造成旧设备退化。
- **页面出现时机**：尚无有效手机连接触发、用户也未主动发起连接时，不因开机主动打开首页。插入 iPhone、收到有效无线手机触发或用户主动连接后，可以立即打开 DiPlay 连接首页并显示连接过程和必要的系统／iPhone 授权；连接成功后继续进入 CarPlay。无需等到后台完全建连才允许显示页面；如果系统阻止拉起，提供受支持的通知或手动入口，不把请求已发送描述为页面已显示。
- **未插手机，手动点击 DiPlay**：正常进入首页，并继续遵循原有自动连接设置。已有会话时复用已有会话和现有进入投屏行为。
- **无线模式**：新增后台模式开启时，未检测到手机就留在原车桌面；检测到手机后可以打开连接首页，不要求全程后台建连。保留既有自动连接、选定手机蓝牙唤醒、热点配置和用户授权语义，不得静默增加新的手动步骤或让现有无线自动连接失效。当前开机无线自动连接会通过 Activity 开始准备，即使尚无手机；能否在等待期间可靠发现手机且不显示首页，需要原型验证。若不能兼顾，必须明确限制并保持开关关闭时旧行为完整，不能宣称无线后台模式已经完成。
- **用户主动断开或切换开关**：设置立即保存，新的开机启动策略从下次开机生效。当前若有后台等待任务，关闭后台启动或开机自启动时应停止等待并取消未完成的唤起；已连接的 CarPlay 不因切换设置断开。启用新开关时不为了立即生效而隐藏用户当前页面。主动断开后不得由同一次排队事件立刻重连；新的明确连接操作或符合既有策略的后续事件如何恢复，应在测试中确认并与旧模式隔离。
- **多次事件与恢复**：开机扫描、USB 插入、蓝牙事件和手动启动需要串行去重。系统回收普通进程、服务异常退出、车机休眠唤醒与用户强行停止是不同场景：前者仅在系统允许且有可靠唤醒入口时恢复；休眠唤醒须核查厂商事件；用户强行停止后不试图绕过系统限制自动复活。快速拔插、授权拒绝、连接失败或取消后不能产生多个控制器、重复弹窗或无限重试。
- **原车高优先级界面**：后台等待期间不能抢占倒车影像、通话等原车界面；连接触发与这些界面重叠时，延迟或进入前台的规则须在实车验证，优先保证原车安全与操作。车机尚在启动、桌面未就绪时收到插线事件也必须验证，不能依靠固定等待时间假定已就绪。

## 建议架构

```text
BOOT_COMPLETED
  ├─ 自启动关闭 → 不由开机自启动入口主动启动页面／等待服务
  ├─ 后台启动关闭 → 现有 DiPlayActivity 开机路径（保持原逻辑）
  └─ 后台启动开启 → 轻量启动协调器
       ├─ 读取开关、连接偏好与授权状态
       ├─ 扫描开机前已连接的 iPhone
       ├─ 监听／接收后续设备事件，并处理无线唤醒
       └─ 有效连接触发 → 串行去重 → 既有连接／授权入口 → CarPlay
```

1. **开机路由**：在 `BootReceiver` 按新增偏好分流，关闭时原 Intent、flags、异常处理和诊断保持原样，同时保留现有电话监听等非页面启动职责。后台路径只由明确开启的偏好进入，避免影响手动启动、USB 系统入口或蓝牙唤醒入口。
2. **等待与事件协调**：为后台等待建立轻量、生命周期明确的协调器，统一处理开机前设备扫描、后续 USB 插入、服务重建和去重。Android 8+ 如需持续监听，可采用符合系统要求的前台服务及低优先级通知；是否必须常驻服务由原型和各版本系统行为验证决定，不能假设进程会永久存活。
3. **连接与界面交接**：优先复用现有 `DiPlayActivity` 的权限与连接流程：检测到手机或用户主动发起连接时即可打开连接首页及授权界面，连接完成后按既有规则显示 CarPlay。不要创建不可见 Activity 再立即退到后台。新增后台模式下，无线开机阶段不能仅因尝试启动而显示首页；先验证无需新增用户操作的手机发现和触发方式。如确实需要抽离无线监听等启动能力，应单独评估最小改动，不要求整个 CarPlay 会话在后台建立。
4. **车机与 Android 兼容**：车机优先验证 Android 8.1 等实际系统；新 Android 版本按可用的 USB 系统入口、用户授权和后台启动规则设计降级。不能保证普通后台服务在任何版本都能直接拉起 Activity。必要时通过可见通知或用户操作恢复，并明确记录限制；不引入强制 ADB、root 或新增常驻高敏权限作为基础前提。
5. **权限与资源**：先检查已有权限，缺失时将用户带入可见授权流程；后台等待阶段不提前申请麦克风、定位或启动音视频。实际连接阶段按系统允许的生命周期启动所需服务。停止等待时释放监听器、线程、通知，避免影响已有连接。
6. **连接状态与诊断**：采用单一状态源，如 `disabled / waiting / permission-needed / connecting / connected / stopped`，与现有会话状态对齐。开关关闭、主动断开或重启等待时更新代次，所有延迟任务与旧回调必须核对代次后才能启动页面或连接；清理完成后迟到事件不得恢复旧任务。记录启动入口、模式、设备匹配、授权、连接触发与失败原因，不记录序列号、蓝牙地址、USB 原始信息、凭据或语音内容；日志不用于承诺真实车机一定已显示页面。

### 需先验证的关键技术选择

#### 无线主动连接原型审查（2026-10-27）

- 现有无线链路在 `CarPlayController.runWireless()` 中先启动或接入 Wi-Fi、准备 AirPlay 监听及 Bonjour，再向已选 iPhone 的 iAP2 RFCOMM 服务主动连接。开机后的蓝牙 ACL 广播不覆盖“手机尚未建立系统蓝牙连接，但车机主动连接”的情形，因此不能单靠 ACL 唤醒替代原有自动连接。
- 把 RFCOMM 提前当作探测手段再关闭、然后由页面重连，会新增一次真实蓝牙连接，可能与 iPhone 现有握手、系统 ACL 事件或自动重连竞争；当前没有证据证明它与三种无线网络模式兼容。另一种做法是由后台持有并移交同一连接，但需要保证手机握手时限、Wi-Fi/Bonjour 的准备顺序、套接字所有权和超时取消；这些都需要真实 iPhone 和车机验证，不能凭模拟器断言。
- Android 10 及以上系统可限制从后台拉起 Activity；运行前台服务并不自动获得页面拉起权限。模拟器上 `startActivity` 返回成功也不足以证明页面已显示。应分别记录检测、系统是否允许拉起、用户可见的降级入口和连接结果。
- 当前增加了默认关闭的设置、后台主动 RFCOMM 尝试及同一套接字的移交；它们仍需真实 iPhone 和车机验证。设置关闭时走原有连接路径。页面被系统拦截时，通过通知提供手动入口；若系统通知权限也受限，该降级入口同样可能不可见。

- Android USB 设备附着事件的可用接收方式、默认处理应用和不同固件是否真正允许自动进入 CarPlay；不能将普通 USB 动态广播当作保证拉起页面的依据。
- 无线模式下验证是否存在无需额外操作、足以覆盖原有连接模式的手机出现／连接事件。现有选定手机蓝牙唤醒默认为关闭，不能假定所有配置都有这个事件；某些模式可能需要后台监听或其他架构调整。必须证明手机不在场时不打开首页、手机出现后仍可触发连接；无法兼顾时明确限制，不能声称完成。此验证不要求连接过程全程在后台运行。
- 车机冷启动、快速唤醒、进程被杀与厂商自启动管理的实际行为；`BOOT_COMPLETED` 不一定覆盖所有休眠恢复。
- Android 10+ 后台 Activity 启动限制；Android 12+ 前台服务启动限制；Android 11+ 和新版本对后台麦克风／定位的限制。按 [Android 后台 Activity 启动限制](https://developer.android.com/guide/components/activities/background-starts) 和 [前台服务启动限制](https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start) 验证实际路径。

## 分批实施与验收

1. **基线与原型**：记录 1.2.0 的开机、已插／后插 USB、无线、自启动与三个连接相关设置组合；针对林肯车机验证 USB 系统入口、无线后台启动和页面拉起可行性。后台模式未实现或验证不足时不开放入口。
2. **设置和开机分流**：新增默认关闭的设置、备份与诊断，接入现有设置行；验证关闭／升级路径行为与 1.2.0 一致。设置页需保留紧凑窗口与大字体完整窗口的截图证据，使用简体中文或英文，并覆盖 1920×1080、2640×1200、1920×720 主要场景。
3. **后台等待和连接交接**：实现有线设备扫描、后插唤醒、授权、状态去重和清理；覆盖手动进入、已有会话、用户断开、开关变更后的迟到事件、拔插、服务重建、重复事件、认证器、其他 Apple 配件和失败恢复。
4. **无线兼容与系统降级**：核对 Wi-Fi Direct、车载热点、已有 Wi-Fi 及选定 iPhone 蓝牙唤醒；满足用户原有无线自动连接配置，不可悄悄降低能力。Android 高版本受限时提供可理解的可见降级，不能影响旧模式。
5. **对抗性审查和实机验收**：覆盖自启动开／关、后台启动开／关、页面自动连接开／关、蓝牙唤醒开／关、USB 预插／后插、无线、首次／已授权、断开和重连、手动启动、导航中返回、倒车影像／电话、开机尚未就绪时插线，以及车机冷启动／休眠唤醒。分别验证普通进程回收与用户强行停止，不将二者等同。测试主链路状态、相同设备多次触发、权限拒绝、控制器与 Surface 资源释放；重点检查开关关闭时与 1.2.0 的差异。不得仅凭模拟器或单元测试声称实车自动拉起已验证。

## 成功标准

- 用户开启后台启动并重启车机，尚无有效手机连接触发、用户也未主动发起连接时保留原车桌面，DiPlay 首页不覆盖或闪现；即使默认选择无线且原有自动连接开启也要验证这一点。手动打开仍进入首页。有线插入或无线手机连接触发后，允许立即打开 DiPlay 连接首页。
- 在车机支持且权限已满足的情况下，iPhone 开机前已插入或开机后插入按上表及各自开关进入既有 CarPlay 流程；连接触发后允许展示连接／授权页面，无重复会话、无限授权或异常返回堆栈。
- 无线开机自动连接在后台模式下经对应模式验证；如有系统或设备限制，必须清楚标明尚未覆盖的范围，不能以无线能力退化作为完整交付。
- 新开关关闭或未设置时，旧版本现有行为无回退；无线及已建立会话不受新增后台模式影响。
- 1920×1080 林肯车机为主要实机验收；2640×1200 华为手机用于调试，1920×720 超宽屏保留兼容检查。
- 自动化测试与对抗性审查通过，并明确列出实际验证过的 Android 版本、设备、授权状态及未覆盖的场景。
