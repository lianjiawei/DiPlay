# CorsairPlay precision.16-rc1

在 precision.15-rc1 上适配有线重连、通话音频恢复与多指触控，供林肯车机和手机接收端测试。

## 改动

- 数据线保持连接、退出后再连接时，若 iPhone 的 USB 网络晚于启动请求就绪，并且就绪后两秒仍未尝试连接 AirPlay，补发一次启动请求。已建立会话或已经开始连接时不补发。补发只允许一次延长启动时限，旧定时回调不会误伤新的等待阶段。
- 挂断或关闭音频会话时撤销本进程的通话音频模式请求，让 Android 继续服从原车电话等其他持有者，或恢复正常媒体模式，避免把先前的通话模式再次占住。
- 双指缩放时，各手指保留稳定的触控槽位；抬起、取消或打开菜单时，在最后坐标释放，避免跳到屏幕角落。
- 为多指下滑菜单保留最长 80 毫秒的手指到齐时间；抬指点击和超过移动阈值的拖动立即发送。关闭菜单手势时不等待。打开菜单、返回首页、退出页面或重建连接会清理尚未发送的触摸。
- 有线超时诊断增加有界的 NCM 帧和连接尝试计数，只解析包头，不记录载荷或连接凭据。

## 适配边界

保留林肯仪表、方向盘、原车语音助手协作、导航压低音乐、音量渐变、音乐时钟优化、USB 重枚举、已插线启动和 precision.15 的横竖屏 UI。

不包含 BYD DiYou 桌面入口修复、桌面悬浮球或其他上游新功能。维持最低 Android 7.1（API 25）、包名与既有发布签名，版本代码递增为 71。

## 测试重点

自动回归覆盖补发请求次数、正常连接不补发、断开时停止等待、旧看门狗失效、双指交换顺序与取消、三指菜单防误触、原车仍持有通话模式，以及旧系统兼容性。发布前执行完整 Android CI、Release Lint、签名和 APK 完整性检查。

自动化不代替林肯实车与 iPhone 验证。请重点测试：

1. 数据线不拔，断开后重连、退出应用后重新打开。
2. 接听、拨出、连续通话及通话中拔线，确认挂断后的音乐、导航、Siri 与原车电话正常。
3. 地图双指缩放（先抬起第一根手指）、普通点击拖动、三指下滑菜单，检查是否有跳动或误点。

默认三指菜单可与双指地图缩放共存；若将菜单设为两指，下滑手势仍会优先占用两指触摸，这是现有设置行为。
