# 林肯仪表进度填充异常：本地回放与保守方案

状态：本方案已实现并完成针对性回归；保留此前后台启动、有线连接和终点相关修改。用户描述为：进度外框、转向箭头和距离仍在，进度填充偶尔看似清空后又恢复；兼容开关关闭。该描述不等同于已测得仪表的 `BargraphSteps` 为 0，无法仅凭合成回放证明已解决实车画面。

## 可证实的发送链路

用户提供的 InstrumentPanel 1.0 将 `INFO` 内距离与合成坐标用于计算进度：当身份不变且起始距离非零时，`BargraphSteps = 当前距离 / 起始距离 × 256`；身份变化时以当前距离重设基准。APK 将进度、方向与显示距离打包交给车机服务，最终仪表绘制不在这份 APK 中。`INFO` 已被 Android 接受不代表接收器或固件已更新。

基于 `v1.2.0` 的合成回放通过实际 TLV 解析、快照、默认仪表广播和 APK 公式模型验证同一路口 `900 → 800 → 0 → 780 → 760 → 740` 米，兼容开关关闭。800 米时基准为 900、进度为 227；旧实现将 0 米立即发送，进度变为 0；随后确认回升、换身份，进度变为 256。现在 `transientZeroThenOrdinaryDistancePreservesProgressAndTheBaseline` 断言该单帧 0 未被发送，恢复的距离继续使用原身份。这是**合成输入可复现的数值链路**，不证明照片或实车当时发生过 0 米或真实画面如何绘制。即使为 0，方向仍会广播，距离字段也会是 0；若实际观察到距离数字始终维持几百米，该链路单独不能解释它。

另一回放 `missingInitialDistanceIsIndistinguishableFromDefaultZeroInCurrentOutput` 验证：新会话只有动作和索引而没有 `0x0a` 距离字段时，当前解析器使用默认 0，输出以 0 为基准并得到接收器默认进度 1；第一条真实 800 米后会换身份、进度 256。距离字段先于索引到达是另一种合法顺序，`distanceRevision` 在当时可能并不增长，不可仅凭修订号推断距离从未提供。该场景主要涉及启动、新路线或丢失状态后的首条信息，不能据此归因于本次行驶中的现象。

已验证的其余边界：同一索引曾回升但后续连续下降，当前回升确认仍可能换身份；只跨过 500 或 483 米不会在发送端自动换身份。约 483 米的仪表 `PropertyOfDistance` 与进度一起发给固件，但固件如何绘制未知。路线剩余距离、时间变更可能重复触发内容相同的 INFO，即使剩余开关关闭；一秒保活本身是原有防闪烁措施，不应直接关闭。

## 已实现的窄范围保护

仅在用户已验证的默认仪表接收包上处理，其他接收包保持原样。以**上一次成功提交的 INFO**为稳定输出；Android 成功不证明实际投递，因此不假装知道仪表当前基准。新措施不改变共享解析器、手机端显示或其他车型导航语义。

1. **同一路口突降到零**：当前已发送的同一路口有效距离不小于 50 米、路线代次/索引及方向没变、没有结束或重规划状态时，首次收到新的显式 0 米作为待确认候选，不把它交给进度跟踪器或立即发送。50 米是防误判的工程阈值，不是协议规定，不能声称最优；实际到达时可能短暂保持旧距离。普通递减、低于阈值的真实 0 和非零距离继续沿用原逻辑；候选期间路名补充可能随旧信息短暂保留，方向变化则优先更新。
2. **等待期间保持已有内容**：保留上次成功 INFO 的方向、距离和身份，继续正常一秒保活；不发送候选 0，也不先污染进度跟踪器的最低距离。保持期内显示会暂时沿用旧距离，并非车机确认保留了进度。保持时间只针对异常候选，不应成为普遍的更新延迟。
   兼容模式下，若环岛等动作的主通道方向相同但辅助通道方向发生变化，辅助通道立即使用上一条有效距离和身份更新方向；等待期间开启兼容模式也先发送这条有效指引，避免漏发方向或把待确认的 0 传出去。
3. **确认与恢复**：候选后若出现有效的同路口非零距离，取消候选并将其交回递减/回升规则；若至少两个真正新距离帧明确为 0，且确认帧距首帧至少 500 毫秒，则接受 0。重复读取快照、歌词和定时保活不能充当确认。同一路口的导航快照仍有效时，等待约两秒后若一直没有可用新距离帧，按 1.2.0 对原 0 值的处理回退；等待时间不是真实性证明，定时器受调度影响。短暂空快照不会重置候选计时；若持续没有有效动作，继续沿用既有空帧保持逻辑，直至有效动作、明确结束或断连，并不保证严格两秒内改变显示。
4. **终点与路口转换优先**：真实结束、断连、已知下一路口、明确重规划，以及未完成首条导航/没有上一条成功 INFO 的场景，不进入远距离 0 候选等待，维持原路径；不得拿上一个路口的旧箭头冒充新路口。首次缺距离的问题先增加是否提供过真实距离的诊断，不直接延迟首次指引；在缺少样本时永久等距离可能引发之前已发现的空白回退。
5. **减少无关重复**：默认仪表主 INFO 的去重 key 比较动作、路口距离、路名、身份以及兼容模式下的辅助转向；路线总剩余变化继续经 REMAIN 独立输出。自定义接收包保留原策略。保留现有一秒 INFO 保活、状态变化和发送异常恢复；不能因没有新候选而长期不发任何保活。旧数据已通过 Android 广播成功不等于实际接收，发送失败和接收端重启仍按现有保护处理。
6. **轻量诊断**：在现有有界内存记录中增加候选开始/确认/取消/超时及原因、数值和路口代次，另以有界计数区分内容变化触发的 INFO 和一秒保活，便于自然使用时关联。只做内存计数，不记录路名、坐标、原始载荷；导出时汇总。当前日志会对重复输出去重，不能推断每次 INFO 的实际到达或固件绘制。

7. **回升后连续下降**：对比最低值回升 5～49 米的候选，若原有 5 秒确认时最近新帧仍在下降，最多额外保持 2 秒等待回落；持续未回落时允许按原逻辑重建基准。50 米及以上回升的原有确认不变，避免过度延迟真实绕路。正常递减和明确重规划无需等待。

## 对抗性取舍与验收

- 特别检查 `900→800→0→780→760`（拒绝一次异常零且不丢失旧进度身份），持续或真实 0（有界等待后可到达），接近路口真 0（立即沿用旧行为），新路口/终点/重规划/断连插入候选期（不能显示错误的旧箭头）。
- 验证先距离后索引、先索引后距离、距离缺失、两项列表、短暂空帧和重复帧；不能把时间相邻当作证明新距离属于新索引，也不将距离默认值与真实 0 混为一谈。
- 验证计时边界、长时间无帧、进程/仪表重启、接收端任意首包/丢包、发送失败及结果不确定、音源切换、旧快照回调、兼容开关和自定义接收器。按 APK 的无钳制进度公式验证同一身份的发送距离不增，避免超过 256。
- 验证总剩余距离/时间独立更新、导航/音乐互不干扰、精度和负数保护不回退；普通距离递减不得额外延迟，定时保活仍按原策略发送。
- 没有真实手机异常帧或固件绘制证据，本方案无法证明覆盖该车现象。对同一输入，短暂假零和长间隔后真正到达可能不可区分：选择有界确认可减小单帧误报，同时存在最长约两秒的显示滞后及超时回退仍可能发出假零的风险；两者不能同时完全消除。
