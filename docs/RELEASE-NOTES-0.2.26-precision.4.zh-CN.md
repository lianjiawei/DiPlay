# CorsairPlay 0.2.26-precision.4

基于个人版 `0.2.26-precision.3`，整合两轮经过回归检查的性能修复，继续使用 `lincoln-0.2.20` 分支。

- 日志初始化、轮转和写入交给一个有界后台写入器，减少主线程及音频诊断回调中的磁盘等待。正常负载下保留已接受记录的顺序、原始时间、脱敏和八份日志历史；新旧会话隔离，关闭后仍写完已接受尾部。
- 后台导出和主动退出最多等待此前日志批次 1 秒；报告显示等待结果与队列丢弃计数，慢存储不会导致无限等待。
- 当前 Host 不接收的原始协议 TRACE 在构造文本之前跳过，减少触控等控制命令中的无效格式化。需要原始跟踪的其他消费者仍默认接收，控制命令发送内容保持一致。
- 最新版及历史版的下载百分比局部刷新，避免反复重建“关于”页，保留焦点；既有下载弹窗、收起重开、校验、重试和安装入口保留。
- 视频帧入队改为直接遍历计数，减少临时集合分配，保留队列阈值、丢帧与关键帧恢复逻辑。

包名为 `com.corsairplay`，versionCode 为 51，沿用此前个人版签名，可覆盖安装同签名的 `0.2.26-precision.3`。更新源仍为 `lianjiawei/DiPlay` 的 GitHub Releases。外置运行时认证资源沿用上一版；不更换认证身份，也不将这些文件纳入公开源码。

发布检查覆盖仓库要求的三个模块单元测试、三个 Debug 构建及 Lint，以及 Release 构建、Lint、认证资源检查、APK 签名和文件校验。具体构建结果、APK SHA-256 与对应源码提交记录在 GitHub Release 中。

本轮没有调整连接状态机、PCM 数据、音频焦点、音量或导航协议，也不据此宣称修复了所有实车声音异常。未连接真实车机测量性能或验证安装及 iPhone 连接。

后台日志最多容纳 1024 个待处理条目，另有一个正在处理的条目；持续拥塞时丢弃最旧待写条目并记录计数。强杀或断电仍可能丢失未写出的异步日志。触控慢链路下的执行队列积压留待专项验证，本版未修改该队列。

源码分析、复现与防退化检查见 [性能审查](PERFORMANCE-REVIEW-2026-10-19.zh-CN.md) 和 [日志写入修复](ASYNC-SESSION-LOG-2026-10-19.zh-CN.md)。两篇文档末尾的本地验证状态记录对应各自完成时的阶段，本次发布将这些修改统一纳入此版本。
