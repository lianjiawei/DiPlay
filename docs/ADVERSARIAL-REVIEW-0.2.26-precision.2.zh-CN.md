# 0.2.26 同步后的对抗性审查与修复

审查基线：`faa24cc3bdd601afb38cfc1c8bb1edd20b01c804`，包含上游正式 `v0.2.26`（`df93896969ad8e9000f099ad9e0999d96df2b48a`）和此前个人修复。本次沿用 `lincoln-0.2.20`，个人版本升为 `0.2.26-precision.2`、versionCode 49，应用 ID 仍为 `com.corsairplay`。

## 确认的问题与处理

| 问题现象 | 源码原因 | 本次修复 | 防止回退的边界 |
| --- | --- | --- | --- |
| USB 已切换配置，却一直等待连接；可发生在启动前已插线的使用流程中 | 初始发现本来有扫描，但重枚举阶段只依赖附加广播，没有重新扫描或阶段超时 | 每 300 毫秒扫描；每轮最多等待约 30 秒，超时报告失败，交给原有重连流程 | 不把仍存在的旧节点当成新枚举；支持同地址先消失后出现、描述符改变和合法附加广播；排除切换前已连接的其他手机 |
| 重复申请权限、旧事件推动新的切换，或慢回调把状态退回“等待” | 广播、权限请求和异步模式切换没有一致的当前轮次检查 | 权限按设备、阶段和轮次去重；排队事件验证接收时的阶段；模式回调验证等待对象归属 | 新节点先出现时立即继续，不等慢模式回调；保留旧 iOS 拒绝模式切换后的数据通路回退；关闭、替换、超时后旧任务失效 |
| 重连后被上一轮报错打断；关闭后还访问旧 USB 设备 | USBMUX 异步打开回调缺少失效检查；进入控制栈前关闭的分支没有释放 USBMUX 会话 | 回调检查轮次、阶段和关闭状态；丢弃过期失败、释放过期成功会话；补齐提前退出的资源释放 | 接口打开和配对正常路径不变；NCM 与 USBMUX 在提前退出时都关闭 |
| PCM 偶发短缺、声音不连续 | 上次个人合并为避免永久循环，在阻塞写入第一次返回 0 时直接丢弃未写完部分；短暂返回 0 也会触发 | 阻塞模式同样允许短暂重试，连续无进展达到 100 毫秒才退出；增加限量诊断 | 非阻塞仍先尝试、再回退；持续返回 0 不永久循环；部分写入保持字节顺序，重试增益从原始 PCM 重算 |

USB 缺口属于原有代码问题，不能据此认定本次车机故障的唯一根因。PCM 的立即退出策略是上次个人合并中的保护过强，本次收窄处理条件。若底层原生阻塞写入自身永不返回，应用层的重试计时不能中断该调用。

## 之前的个人修改是否仍有价值

| 修改 | 重新审视后的决定 | 原因与证据 |
| --- | --- | --- |
| 旧的自定义 PCM 写入循环 | 已在上次合并中移除，继续使用上游 `PcmChunkWriter` | 上游已提供分块与非阻塞方案，重复维护没有价值；本次仅修正必要的扩展边界 |
| PCM 重试时刷新静音／增益 | 保留 | 上游每块只准备一次；等待期间的静音变化可能遗漏。撤掉此扩展后，2 个输出数据断言失败 |
| 阻塞写入返回 0 的保护 | 调整 | 永久无进展保护仍有价值，但第一次返回 0 就退出过于激进；改为有时间上限的重试 |
| 系统与车机实体静音来源区分、解除静音校正 | 保留 | 上游仍可能缓存失效的系统静音状态；只修复推断的 SYSTEM 状态，保留明确的 CAR 静音。撤掉校正后 6 个用例失败 |
| 时钟拥塞保护与保留已学习的漂移 | 条件保留 | 仅用户启用时钟微调时生效，不改变上游默认关闭策略。撤掉高水位保护后 2 个用例失败；不能据此承诺解决所有 HAL 杂音 |
| 焦点中断延迟恢复的会话／意图检查 | 保留 | 上游的新播放互斥逻辑没有替代旧回调的归属检查。单独撤掉手动操作取消恢复后，1 个“手动暂停却被重新播放”用例失败；完整焦点测试同时覆盖断开与重复 GAIN |
| 仪表导航结束清屏、重复来源事件处理 | 保留 | 即使快照相同也要推进结束计时。加回旧的相同快照提前返回后，3 个清屏用例失败 |
| 备份服务停止时等待监听线程结束 | 保留 | 上游停止操作仍不等待；快速重新打开有端口占用竞态。继续由固定端口反复启停测试覆盖 |
| 个人更新源、缓存来源与版本比较 | 保留 | 个人包签名与原作者发布包不同；错误更新源会使覆盖安装失败。此项属于发布兼容性要求 |
| 5 米／50 米／500 米导航距离精度 | 保留为用户偏好 | 这是显示策略，不是稳定性补丁；只作用于仪表转向距离，不改路线剩余距离。真实仪表如何格式化 0.5 公里仍需接收端或实车确认 |
| 上游已补齐的旧翻译 | 已随合并采用上游版本 | 不再叠加重复修改；保留 0.2.26 新桌面实验功能需要的缺失翻译及实验标识 |

逐项撤除实验共执行 47 项检查，预期重现 14 项失败；每轮只撤一个行为，结束后校验源码逐字节恢复。它证明补丁保护的行为仍会退化，不证明用户上传日志中的每次降音都由这些路径触发。

## 复现方法与覆盖范围

- 首轮修复前执行 38 项定向检查，21 项失败；包含广播丢失、等待超时、旧回调与阻塞短暂返回 0。
- 第二轮主动构造本次修复可能引入的时序问题：旧附加事件排队跨阶段、新节点先于模式响应出现。4 项用例先失败，修正后通过。
- 另对过期 USB 会话成功／失败、关闭后访问旧设备执行 6 项检查，修复前全部失败。
- 新增 `WiredUsbRecoveryTest` 在 Android API 27 与 33 运行，使用模拟 USB 主机、设备和可控主线程，覆盖已有设备发现、晚出现、广播与轮询去重、旧节点、同地址复用、其他已连接手机、临时扫描失败、超时、旧 iOS 回退和资源释放。
- PCM 用例核对实际写出的字节及顺序，覆盖短暂与永久零进展、部分写入、取消和实时增益变化；不以“函数返回”代替数据完整性检查。

## 启动条件与实车限制

本次没有改变开机自启、打开应用时连接、默认有线／无线模式。这些是独立的用户设置。若应用根本没有启动、有线控制器没有运行、Android 未列出设备或 USB 权限未授予，重枚举轮询不能替代这些前提。

“开机前插线”应分层定位：应用有没有打开 → 是否自动发起连接 → 实际使用有线还是无线 → USB 是否列出设备 → 是否停在重枚举。本次修复的是最后一段的确定代码缺口，不能承诺解决固件不发送开机事件或限制启动的问题。

无真实车机／iPhone 连接；尚需实车验证冷启动前插线、热插拔、无线重连、随心听互斥、方向盘切歌、通话／Siri、静音恢复及仪表导航。自动化通过不等于实车零回退。
